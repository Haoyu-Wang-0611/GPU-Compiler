## 2. 四臂（与 spec v2 §2 一致）

| 臂 | 定义 |
|---|---|
| A0 | 三行规则 `R_full`：块数≥SM（退 SM/2，再退 0）→ 最大 tile 面积 → 最大 TK → S=1 |
| A1 | v1.8.5：`cchunk=0`、`L2_BOOST=1` |
| A2 | v1.8.5 + `cChunk=150` + `L2_BOOST=2`（当前 `decide_dev` 默认） |
| A3 | oracle：同候选空间穷举实测最优 |

**主指标**：tie-aware top-1 命中率（τ = max(2%, 前 10% IQR)）。
**副指标**：名次百分位、regret、双达标、false-pruning、前沿压缩率、决策耗时、绝对预测误差。
**不混用**：主指标只看命中；rank/regret 只做分布；"前 20%"不是主指标。

## 3. 预测（先写死，逐条可证伪）

### P1｜总体：A2 不劣于 A1、A1 不劣于 A0

- P1a：A2 的中位 regret ≤ A1 的中位 regret（12 主集）；
- P1b：A2 的命中数 ≥ A1 的命中数；
- P1c：A1 的中位 regret ≤ A0 的中位 regret。

> 若 A2 的中位 regret **大于** A0：触发"cChunk/L2 作废"（见 §5）。

### P2｜A2 的优势集中在 GEMM/链（R1–R4）

- P2a：R1–R4 四行里，A2 的 regret 至少 2 行**严格小于** A1；
- P2b：这 2 行的差 ≥1 个百分点（不是数值噪声）。

理由：cChunk 只对 GEMM/链的 TK 维起作用；R2 的 A1/A2 决策相同（预期打平）。

### P3｜A1/A2 在 GEMV 与 2D stencil 上**逐位相同**

- R5、R6、R8、S4、S5 五个 kernel：A1 与 A2 的决策配置完全相同。
- 若不同 → 不是模型差异，是代码路径分叉（bug），先查代码，不得当作科学结果。

### P4｜A2 对 A0：规则在"容量行"输，在"平台/占用行"打平

- P4a：A2 的中位 regret ≤ A0；
- P4b：在 plateau/占用受限行（S4、S5、S6、R5、R6、R8）上，A0 与 A2 的中位 regret 差 ≤3 个百分点；
- P4c：A2 相对 A0 的优势集中在容量行（R1–R4、S1–S3）。

### P5｜前沿覆盖：false-pruning = 0/12

- 12 主集中，oracle winner 全部落在 A2 的收缩后前沿内（false-pruning = 0）；
- 前沿大小中位 ≤30/96（压缩 ≥3.2×）；
- 空集回退触发 ≤2/12（预期 R1/R3/R4 这类 1152 尺寸不触发；若触发，记录）。

### P6｜质量门槛

- A2 的 tie-aware 命中 ≥9/12；
- 双达标（rank 百分位 ≤20% 且 regret ≤20%）≥10/12；
- 主集 12 个全部可测（缺载具 → 用 S7 预注册替换，见 spec §3.1）。

### P7｜深度（探索性，不参与 Go/No-go）

在"容量行"（决策的 smem ≥0.9×cap）中，A2 的 S 等于该 tile 下的 max feasible S（或相差一档）
至少 4/6；否则"深度=容量残余"只能写成经验观察，不能写成规律。

### P8｜决策成本

A2 的单 kernel 决策耗时中位 <1 ms（PC，`holdout_decide.py --reps 20`）。
**注意**：这是决策函数耗时，不含编译/发射；不与 ALCOP 的搜索耗时直接拼表。

### P9｜绝对误差（探索性）

A2 的 predicted vs measured 中位绝对误差 ≤25%。该指标只做 limitation，不作为主张。

## 4. 分析口径（看结果前写死）

1. 每个 kernel 的日志：`daima/oracle_logs/<日期>-holdout/<name>.log`；
2. 每配置 R=5 样本取中位数；τ 由 `four_arms.tau_of` 计算；
3. 并列名次 = `1 + #{配置: t < t_arm×(1−τ)}`；
4. regret = `t_arm / t_best − 1`；命中 = `t_arm ≤ t_best×(1+τ)`；
5. A0 只从**实测日志里存在的配置**中选（规则不假设未测配置）；
6. false-pruning = oracle winner 不在 A2 前沿；若 winner 不在候选空间 → 记协议问题，不计入 false-pruning 但必须报告；
7. 缺日志/缺 PASS 的 kernel → 标"未跑/协议失败"，**不进入分母**，但主集可测数 <10 时整个套件无效。

## 5. Go/No-go 与失败处置

| 条件 | 处置 |
|---|---|
| 主集可测 <10 | 套件无效：先补载具/协议，不得报质量 |
| P5 失败（false-pruning >0） | 前沿实现 bug：修 → 全量重跑；此间不写任何"边界"结论 |
| P3 失败（A1/A2 在 GEMV/2D 不同） | 代码路径 bug：修 → 全量重跑 |
| A2 中位 regret > A0 | **cChunk/L2 作废**：回 v1.8.5；论文只写可行性 + 规则/模型对照 |
| A2 命中 <9/12 或双达标 <10/12 | 按老师三叉判据降级（边界成立/深度不成立 → 去掉 "Depth Is Derived"；两者都不成立 → 回 v1.8.5 + ALCOP 对照） |
| P2 不成立（A2 ≈ A1） | 承认 cChunk/L2 在留出集上无收益；保留更简单的 A1，或只保留"绝对量级修正"的表述 |
| P7 不成立 | 深度从"规律"降为"观察"，不写"导出" |
