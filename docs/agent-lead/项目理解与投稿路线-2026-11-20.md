## 0. 一句话

输入 `affine.mlir` → 窗口/面板分析得到每个数组的 footprint 与工作集 → 五类模板分类 →
96 候选上做「硬可行域（smem/寄存器/结构）+ 占用收缩」→ 两态式成本模型（cChunk 150 ns、L2 regime β=2）打分 →
毫秒级输出 tile/TK/S → 手写 CUDA 载具穷举 oracle 反审计 → 15 行开发集（in-sample）rank/regret。
MLIR 发射只对单 GEMM / stencil 打通，深度的发射语义尚未闭环。

**一句话判断**：工程与证据链已经够一篇 CCF-B 的骨架；现在缺的不是更多 kernel，
而是 **out-of-sample 的裁判数据** 和 **与 ALCOP 的正面对照**。这两样缺任何一样都会掉档。

### 1.3 我复核出的三个"文档里没有明说"的事实

**（1）8 行 GEMM 族里 6 行的 oracle winner 把 smem 用到恰好 98,304 B（96 KB）**，再加一档 S 就越过 99 KB：

| 行 | winner | smem | blocks | 再加一档 |
|---|---|---|---|---|
| gemm4096 | 128/256/16/3 | 96 KB | 512 | S=4 → 120 KB ❌ |
| gemm1024 | 128/64/64/1 | 96 KB | 128 | S=2 → 144 KB ❌ |
| gemm500 | 64/64/64/2 | 96 KB | 64 | S=3 → 128 KB ❌ |
| twomm / three_mm | 64/64/64/2 | 96 KB | 64 | S=3 → 128 KB ❌ |
| symm | 64/64/64/2 | 96 KB | 64 | S=3 → 128 KB ❌ |
| gemm512 | 64/64/64/1 | **64 KB** | 64 | S=2 可行且实测并列（24.2） |
| syrk | 64/64/16/3 | **32 KB** | 64 | 容量远未用满，被守卫粒度拉到 TK=16 |

⇒ **"容量墙"是 8 行里 6 行的真实约束**；剩下 2 行是平台（512）与守卫（syrk），不是容量。

**（2）cChunk 与 L2 regime 是 11-18 同一天加的两个后验项。** 相对 `cchunk=0/β=1`，二者合计改变 **6/15** 决策
（512/500/twomm/three_mm/syrk/symm），rank 1 从 **4→9**；按"先 β 后 cChunk"的顺序，β 单独改 3 行、cChunk 再改 3 行。
两项在参数区间内稳定（cChunk 25–500 ns、β 1–4），但"为什么是这个值/这个区间"只能由留出集回答。

**（3）深度是条件化的容量残余，不是普遍定律。** 容量受限的 6 行 S = max feasible；
512 的 S=1/S=2 实测并列（平台）；syrk 的赢家 S=3，而 S=4 仍装得下（39.0 vs 38.8，噪声级）
——它不是容量残余，而是守卫粒度把 TK 拉到 16；GEMV 的 S 不敏感；stencil 是带宽平台。
⇒ 可写"**条件化深度导出**"，不可写"深度塌缩到 1"或"深度永远 = max feasible"。

## 2. 三个真问题（按对录用的威胁排序）

### 2.1 质量优势目前是 in-sample 的，而且由后验项造出来

- v1.8.5 的 **TK 在模型里不可辨识**：`chunks×copy = K(BM+BN)·4/bw` 与 TK 无关，`chunks×comp` 也与 TK 无关
  → TK 由枚举序决定（512/500/链当时选 TK=32/S=4）。
- cChunk 给 `chunks` 加固定开销 → 偏好大 TK；L2 β=2 改变 copy 量纲 → 两者一起把 6 行翻到大 TK/低 S，
  恰好落在 oracle winner 附近。
- 所以"模型 0.0% vs 规则 3.0%"是**加了两个后验项之后**的数字；在 v1.8.5 上模型中位 **+4.3%**，
  **比 R_full 的 +3.0% 还差**。
- 这不说明模型错，但说明：**15 行表不能再当作质量证据**。审稿人只要问"cChunk 是不是调出来的"，开发集回答不了。
- 注意两份文件口径相反：`48小时审计.md` §11 的"明确不做"里写着"不新增 cChunk 或其他让旧表更好看的拟合项"，
  而 11-18 的修法正是 cChunk，`待做.md` 又把 #1 标为已解决。**论文里只能留一个口径**
  （我的建议：保留 cChunk，但在留出集上按"两臂"检验，把它写成"被独立检验的机理项"而不是"拟合项"）。
- **系统一致性缺口**：cChunk/L2 只活在 `tools/decide_dev.py`；`L1Feas.cpp` 仍是 v1.8.5，没有这两项。
  也就是说"表里最好的模型"目前**不由 MLIR pass 产生**。若论文以当前默认为主，必须把两项落进 C++（v1.9）
  并重跑 16 发回归 + rebase；否则 T1 的决策来自 Python、发射来自 C++——正是老师/Claude 说的"不是同一个系统"。
- **历史细节（cChunk 的来源）**：cChunk 的最初动机是 `docs/必要性重分析-512-2026-11-14.md`，
  它用的是 `sweep_512.log` / `sweep_512_S4.log`——而这两份后来被 H1 判为整轮 +12% 的污染轮。
  干净卡上 TK 偏好方向仍成立（TK=64/S=1 24.2 vs TK=32/S=4 25.5），但 **cChunk 的数值不能从那两份日志反解**
  （CHANGELOG 也记了"反解失败，斜率 162–527 ns 随尺寸变"）。它只能当名义值，必须在留出集上做区间检验。
- 唯一解毒剂：**预注册 + 留出集 + v1.8.5 与 v1.9 同场对比**（见 §4）。

### 2.2 深度叙事与发射语义脱节

- 载具的 S 是 `B=S+1` 缓冲、`D=S` 预取（`sgemm_tiled.cu` 主循环已核：S=1 时预取在 compute 之后、串行；S≥2 才有重叠）；
  模型的 S≥2 分支对 S **平坦**（`chunks×max(copy,comp,Lcap)` 与 S 无关），S 只由容量与 expo 区分。
- 机理上，`必要性重分析-512` §4.1 已经指出：**tile 与 depth 在这套载具里是替代品**（加大 TK 与加深流水
  都在提高"计算/同步"比）——这正是"容量残余"的来源，也说明"深度导出"只能在容量受限/低占用这两类里成立。
- `B线` F1/F2 已把机理说透：满占用搬运主导区 S=1→S≥2 是 **−21% 阶跃**（4096³ 64×64/TK16），
  S∈{2,3,4} 展宽 **0.5%**。所以**不能既说"深度被优化"又说"深度组内展宽 ≤1%"**；
  正确写法是"模型判定深度已饱和，给出 S 的最小可行值"。
- 发射器只设 `iteration_interval = ceil(maxCycle/(S-1))`，**没有 num_stages**；stencil-2d 是行带流式，不是模型 2D tile。
- ⇒ 现在能说的是"**载具语义下**深度是容量残余 + D≥2 饱和 + lane×DRAM 双条件"；
  不能说"MLIR 发射的深度按模型决策"。
- 若做 E3，必须先做 4×2 `(num_stages, II)` 发射矩阵，数 smem/克隆，建立 `(B,D) ↔ (numStages,II)` 映射；
  否则切片会给出"深度没用"的假结论（DeepSeek2 已警告）。

### 2.3 与 ALCOP/ICS'21 的差异还没变成证据

- ALCOP 的 79%/92% 是 analytical ranking 取 top-10/top-50 再实测取最佳，**不是 direct top-1**（Claude 已核实）。
  直接拿两个百分比对比会被拒。
- 原文摘要还给了另一个数字：**"99% of exhaustive search while costing 40× fewer trials"**。
  也就是说"质量—成本"这条叙事 ALCOP 已经占了；我们不能只说"我们 3.7 ms、它几分钟"，
  必须说清楚差别是 **0 次 trial（无编译/执行反馈）vs 40× fewer trials**，并且质量要在同套件上不低于它。
- 需要：同候选空间、同载具/同套件、同一测量协议的**质量—成本曲线**
  （本方法 direct top-1 无执行反馈 vs ALCOP analytical-only vs ALCOP full）。
- "硬可行域"是否独有也需核实原文（不能因为 ALCOP 没写不等式就推断它没有）。
- **ICS'21 已经把"资源约束下 affine tile 直接选择"做过了**：ILP 约束 + PPCG 交叉编译，只生成两条配置，
  PolyBench 上约 **75% of best empirical tile**（两块 GPU）。所以"tile 直接选择"本身不是新点；
  新点只能是：**depth 进同一个容量预算**、**模板统一（单 GEMM/链/GEMV/守卫）**、以及**接近 oracle 的质量**（留出集证）。
  如果留出集上我们只有 ~75-80%，这篇论文就退化成"ICS'21 + 一个深度节"，需要提前想好退路。

## 3. 论文骨架：两个版本，建议 B

| | A 成本模型中心 | **B regime 中心（建议）** |
|---|---|---|
| 主张 | 解析成本模型在无实测反馈下逼近穷举 | 先用结构/硬件量把 kernel 分到 4 个 regime；每个 regime 只需一条可判定的规则；成本模型只做绝对预测与 tie-break |
| 证据 | 15 行 + 留出 rank/regret | 15 行 + 留出 **regime 预测命中率**（winner 是否在预测的极值上）+ rank/regret |
| 风险 | 与 ICS'21 的 tile-only 直接选择重叠、ALCOP 已占"质量—成本"；我们的质量优势目前只有 3 pt（中位） | 被说成"决策树/专家系统"；需证明 regime 边界由硬件/IR 导出而非调参 |
| 可退可进 | 深度规律不成立就退 | 无论深度成不成立都能立住；深度作为"容量 regime 内的导出"一节 |

> regime 分层的雏形在 `docs/必要性重分析-512-2026-11-14.md` §4.2（搬运主导/容量受限/计算主导/低占用）；
> 本文件把它从"联合必要性"改成"**赢家贴哪面墙**"的预测，并补了 plateau/guard 两类。

**B 的四个 regime（来自 15 行，待留出集检验）**：

1. **容量受限**：winner 把 smem 用满（6/8 GEMM 行，96 KB），S/TK 由容量残余导出；
2. **占用受限**：blocks 落在 SM 或 SM/2（512 的 64 块、atax 的 128 块、mvt/bicg 的 64 块），tile 由"块数≥线"约束；
3. **带宽平台**：jacobi1d / heat1d（DRAM/L2 饱和），配置在噪声带内不可分；
4. **守卫/延迟受限**：syrk（32 KB、TK=16，守卫粒度）、mvt/bicg（107 GB/s，延迟受限）
   ——**这是模型的边界，要显式声明，不是藏起来**。

> 行可以同时落在两个 regime（mvt/bicg 既在占用线、又受延迟限制）；这里说的是"预测赢家所在的极值"，
> 不是互斥分区。留出集要检验的是：**预测的 binding regime 是否真的是赢家贴住的那一面**。
>
> 另外，regime 不是每张卡固定：`B线` P2 用 `comp/copy` 与 `blocks/numSms` 两个无量纲数预测
> **4090 搬运主导（0.49）vs A100 计算主导（1.70）**，换卡后 depth 从饱和变成有真实收益
> ——这是第二张卡的科学价值，不只是可移植性。

**可辩护的三层主张**：

- **A 构造性硬可行域**（窗口/面板 footprint + 寄存器 + 结构）：零非法；能抓住"合并窗口低估 smem"这类真 bug（syrk 160 KB）。
- **B 高覆盖剪枝 + 直接选择**：96→10，无编译/执行反馈，毫秒级；质量不劣于强规则/autotune（留出集判）。
- **C 条件化深度**：容量 regime 内 S = 容量残余；D≥2 饱和；lane×DRAM 双条件。

**明确不写**："最优永远在边界"、"深度不是搜索维度"（普遍版）、"首次"、"任意 kernel 零非法"、
"Measurement-Free"（改为"无编译/执行反馈在环"）。

## 4. 裁判实验：留出集应该这样设计（spec v2 的 5 处改动）

1. **冻结版本改为两臂**：A1 = v1.8.5（旧）、A2 = v1.8.5 + cChunk150 + L2β2（当前 `decide_dev` 默认，**尚未进 C++**），
   同一实现；另加 A0 = R_full 规则、A3 = oracle。**四臂同场**，才能回答"后验项值不值"。
   若 A2 胜出，再在 C++ 落成 v1.9 并重跑回归——留出批可以先离线跑，但论文的"系统证据"必须来自同一实现。
2. **主指标**：tie-aware top-1 命中率（主）；rank 百分位/regret 中位（副）；双达标率 ≥80%（Go/No-go）。三者不混用。
3. **补 H4/H5**：H4 前沿覆盖（oracle winner 是否被收缩后前沿保留，false-pruning = 0/12）；
   H5 regime 预测（winner 是否在预测 regime 的极值上，≥80%）。
4. **结构留出补 2 项**（spec v1 主要测尺寸）：矩形 GEMM（M≠N≠K，载具需参数化）与 2D r=2 halo（A5 已有）；
   若来不及时，在 limitation 明确"本套件是尺寸/半径留出，不是模板留出"。
5. **预注册预测表**（看结果前写死）：A2、A1、A0 的中位 regret 依次不增（A2 ≤ A1 ≤ A0）；
   A0 在 plateau/occupancy regime 与 A2 差 ≤3%；A2 的优势集中在容量 regime；
   **若 A2 < A0 → cChunk/L2 作废，回 v1.8.5**。

**出口**：12 kernel（若加 2 个结构项则 14）、R=5 round-robin、中位 rank ≤20% 且 regret ≤20%、≥80% 双达标、false-pruning = 0。
不达标 → 按老师三叉判据降级（边界成立/深度不成立 → 去掉 "Depth Is Derived"；
两者都不成立 → 回 v1.8.5 + ALCOP 质量—成本对照）。
