## F. 2026-11-15 核查记录（本轮新发现）

1. **15/15 golden 与 `l1_*.txt` 排序后逐行一致**（等价 `regress.sh` 判据）；
   缺 `syrk_probe` 的 golden；清单外多出 `l1_out.txt`（jacobi2d 的重复输出）
   与 `l1_.txt`（58 字节空跑）。
2. **决策参数与主表逐条对上**：4096 = 128×256/16/S3、512/500 = 64×64/32/S4、
   atax = T64/TK64/S1、mvt/bicg = T8/TK64/S1、syrk = 64×64/TK64/S4、twomm/3mm = 64×64/32/S4。
3. **4096 的决策比文档更靠前**：三次会话分别为 rank 1 / 2 / 3，全部落在 0.23% 的并列带内。
   主表的"rank 3/48、距优 +0.4%"是单次会话表述，应改为"1–3/48，并列带内"。
4. **`compile.log` 是 ptxas 详单**：`256×128/TK64` 实例 = **229 registers、0 spill、sm_89**。
   229 regs × 256 threads = 58,624 > 65,536/2 → **寄存器本身就限制到 1 block/SM**。
   这是占用率的第四层，模型（只排除了 256×256）没有算。
5. **`heat1d_2^20.log`（非 redo）的 4 行 2.2 µs 假数据已定位**：
   正是 T=4096/S3,S4 与 T=8192/S1,S2（`cudaFuncSetAttribute` 缺失 → >48 KB launch 静默失败）。
   redo 版对应为 7.2 µs 量级，干净。
6. **主表最弱行 = heat1d @2²⁰（+18.0%，贴 20% 红线）**，且它走的是已知有缺陷的
   1D legacy 分支（launch 语义只计一次 + base 记账）。建议：修分支，或把它降级为
   "回归锚点"而不是质量证据。
7. **探针结构与文档声明一致**：three_mm = 9 环/3 pass、symm_true = 6 环 + 2 个 `affine.if`、

## G. 2026-11-15 第二轮：深度探针 + 三轮复核（结论已改口）

**G1｜驻留假设作废。** `[dev]` 实测 smem/SM = 100 KB（不是 128 KB），regs/SM = 65536、
blocks/SM = 24、threads/SM = 1536。`bufprobe` 在 128×128/TK16 上把缓冲份数 B 与预取距离 D
拆开后：驻留从 3 块降到 1 块，耗时反而从 84.6 → 80.8 µs（512³）。**驻留不是深度的驱动变量。**

**G2｜3mm 的 "+35% 反例"是测量污染。** 同一命令三轮：

| 轮次 | (128,128,16) S=1/2/3/4 |
|---|---|
| 原 | 471.6 / 348.5 / 244.0 / 329.8 |
| rerun1 | 255.3 / 459.6 / 243.3 / 243.1 |
| rerun2 | 284.4 / 244.4 / 336.8 / 248.9 |

**最小值稳定在 243–255，而"慢的那个"每轮落在不同的 S 上**。胜者 64×64/TK64/S2 三轮 75.1/75.3/75.3。
⇒ P1 的反例作废，`derived` 规则的实测支持从 16/16 继续成立。

**G3｜测量不稳定性有三个 regime（本轮最重要的方法学结论）**：

| regime | 证据 | 极差 |
|---|---|---|
| 同会话 + 活跃块 ≥ 半卡 | 3mm 三轮，64 块族 | **0.3%（最大 1.2%）** |
| 同会话 + 活跃块 < 半卡 | 3mm 三轮，≤16/17–63 块族 | **中位 21.7% / 67.6%** |
| 跨会话 + 短 kernel（512³, ~27 µs） | 三份 512 日志 | 中位 15–18% |
| 跨会话 + 长 kernel（4096³, 4.3 ms） | run1/run2/friday | **0.23%** |

⇒ **半机守卫（numBlocks ≥ numSms/2）同时是"性能边界"和"可测性边界"**——这是它此前没有的
理论依据。⇒ 跨会话的 rank/距优 只在 4096 这类长 kernel 上可引；512 只能引"族级胜出"（5× 分离）。

**G4｜唯一仍然成立的 P1 反例：atax T=8。** 两个独立会话复现（955/1174/1235/1238 与
937/1167/1234/1232），深度 +31% 稳定可复现，机理是**块内利用率不足**（8 行活 / 256 线程），
与容量、驻留都无关。⇒ P1 的边界条件应写成"活跃 lane 占比"，不是 smem。

## H. 2026-11-15 第三轮：干净卡（6/7 号）复测 —— 两处改口

**环境**：`guard6.log` 显示 6/7 号卡 0% 占用、210 MHz 空闲；naive 三连 582.0/581.8/581.7
（均值 581.83，极差 0.05%）→ 与 10-29 标定带一致，**本轮为干净卡**。

**H1｜512³ 不飘，"跨会话 15–18% 漂移"是污染，撤回。**
干净卡重跑 48 配置：最优 **24.2 µs @ 64×64/TK64/S1**，模型决策 (64,64,TK32,S4) = **25.5 →
rank 3/48、距优 +5.4%**，与 11-14 的首轮（24.1 / 25.4 / +5.4%）逐项吻合。
⇒ `sweep_512_S1/S4.log` 那两轮（27.1/27.2）是整轮 +12% 膨胀的污染轮，**主表 512 行用 +5.4%**。
⇒ 我此前"短 kernel 跨会话固有 15–18% 漂移"的结论作废；**清洗后 512 与 4096 一样稳（≈0.3–0.5%）**，
不稳定性来自环境，不是 kernel 时长。

**H2｜syrk 定稿为穷举背书：rank 6–8/48、距优 +8.0%。**
三轮干净复现：v2 36.1/+8.0%、v3 38.8/+7.9%、v4 38.7/+8.1%；最优恒为 **64×64/TK16/S3**。
v1（65.9/TK64/S2）确认为污染轮。⇒ 主表守卫形态一行可用。

**H3｜syrk 载具有 1.64× 的额外开销（新 caveat）。**
同一配置 (64,64,TK32,S4)：GEMM 25.5 µs vs syrk **41.8 µs**（1.64×），而两者每 chunk 字节数相同
（GEMM A+B = 2 面板 = syrk 的 2×A）。说明守卫实现的代价高于流量差；且 syrk 最优被拉到 TK=16
（GEMM 是 TK=64）——**更像"chunk 级守卫粒度"效应（小 TK 跳得更准），不是流量结构效应**。
⇒ 论文里守卫形态只能用于"同载具内的决策质量"，不能与 GEMM 的绝对性能并列；
⇒ "守卫粒度"应登记为第四个边界项（模型不建模）。
