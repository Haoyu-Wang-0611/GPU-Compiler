## 0. 一句话结论

**原定的"非对称多缓冲"作为 B 线的技术核心不成立**——在 4090 的 FP32 GEMM 上，
当前模型会给出 17.5%～48% 的"非对称增益"，而那是模型缺少**聚合带宽墙**造成的
假象（你自己的 sweep 已经反证：S≥2 全平）。但这轮判读同时也把 B 线真正的
科学内容逼出来了：**"tile 与 depth 是否耦合"是可以被解析判定的、且判定结论随
架构 regime 翻转**——4090 上耦合退化（depth 二值、tile 主导），A100 上耦合成立
（计算主导，depth 有真收益）。这条主张比"我们做了联合优化"更硬，也正好是
ALCOP/Twill 结构上无法给出的东西（它们只能靠实测发现"这里没什么可调的"）。

## 2. 四个先验结论（都可以用现有数据核对）

### F1 满占用下，`copy` 项恒等于整卡带宽约束 —— 深度不改变总流量

`copy = copyB / 7.21`（每块每 chunk 字节 ÷ 单 SM 带宽）。把同一字节数乘回
128 块再除整卡带宽，得到的数与 `copy` **在公式上恒等**（4096: 3408.6 = 3408.6；
512: 2272.4 = 2272.4）——因为 `chipBw = smBw × 128` 就是这么标定的。物理上
只有在 `numBlocks ≥ 128` 时它才真的是整卡带宽约束；块数不足时它**高估**了可用
带宽（这正是 512³ 半机档模型保守 +49% 的来源）。

推论：满占用 + 搬运主导区里，深度增加不减少任何字节，因此**没有稳态收益**。
实测完全一致：4096³ 64×64/TK=16 的 S=2/3/4 = 6093/6103/6124 µs（0.5% 内），
S=1 = 7393.9 µs（−21%）。这 −21% 是"串行→重叠"的**阶跃**，不是渐进收益。

### F2 在本模型族里，depth 是二值旋钮；S=3/4 多为 0.5% 级 tie-break

S≥2 之后，S 只通过 `expo = max(330/S^1.2, 52)` 与 `L_min` 起作用。对 4096 的
决策配置：expo = 88.3 ns，copy = 3408.6 ns → expo 占 2.6%。所以主表里
S=3/S=4 之间的选择，在模型内部只是噪声级差异。

**这是必须写进论文的诚实项**：不能同时说"深度被优化"和"深度组内展宽 ≤1%"。
正确表述是：模型判定该 kernel 处于"深度已饱和"区，并给出 S 的最小值——
这正是"可判定无需调优"的证据。

### F3 非对称缓冲在当前模型里产生**虚假增益**（17.5% / 48%）

| 方案 | 4096³ 决策 | predicted | 相对对称 |
|---|---|---|---|
| 对称 S | 128×256/16/S=3 | 3.566e6 | — |
| 非对称（min 变体） | 128×256/16/S=(1,2) | 2.945e6 | **−17.5%** |
| 非对称（Little 律） | 128×256/16/S=(3,3) | 1.857e6 | **−48%** |

两个版本都靠"把另一路搬运藏到计算后面"拿到增益，但搬运主导区整卡带宽已饱和，
**藏不住**。你自己的 S 平坦数据就是直接反证。容量前沿检查也显示：99 KB 上限下
4096 没有任何"对称不可行、非对称可行"的配置（`--frontier` 输出为空）——
非对称在那里既不解决容量，也不解决时间。

⇒ **B 线若以非对称缓冲为核心，投稿稿里的核心数字会被自己的 oracle 推翻。**

### F4 半机守卫 + tile 下限 64，在 ≥142 SM 的卡上让 512³ **全空间不可行**

`numBlocks >= numSms/2` 与 `BM,BN ∈ {64,128,256}` 一起，导致 512³ 在 142 SM 上
最大只能凑出 8×8=64 块（64×64），而门槛是 71 → **0/96 可行**
（`--compare-hw` 已复现）。

影响面：H100(132 SM)、RTX 6000 Ada(142 SM)、B200 都会踩。审稿人只要换一张卡
复现就会撞上"no feasible config"。**必须修**：候选下探到 32，或把守卫改成
软惩罚（占用不足 → 时间乘子），并给出"为什么不是硬拒"的判据。

## 3. B 线重新界定：从"联合优化"到"**可判定的耦合**"

### 3.1 主张

> 一个构造性（无实测反馈）的容量耦合模型，能够在**决策之前判定**某个 kernel
> 在给定机器上 tile 与 depth 是否真正耦合：耦合成立时给出联合决策，不成立时
> 证明"depth 已饱和、只需 tile"；该判定随架构 compute/bandwidth 比翻转，并在
> 两块卡上被穷举实测双向验证。

三根支柱（对应三篇现有工作的缺口）：

1. **构造性硬可行域**：窗口法 + 容量耦合 + 寄存器上限，**从不产生非法配置**
   （ALCOP 的容量只进 occupancy 模拟，实测有 compile-fail 配置；Twill 有硬约束
   但要 19–269 s 求解）。
2. **三机理项**：两态阶跃（S=1 串行 / S≥2 重叠）、per-chunk 流水下界 `L_min`、
   **聚合带宽墙**（B 线新增，见 3.2）。前两项已有实测出处（10-31、11-02），
   第三项是把 F1 从"巧合"变成"模型的显式约束"。
3. **regime 可判定**：`comp/copy` 与 `blocks/numSms` 两个无量纲数决定
   "depth 是否值得调"，判定结果可被"扫参展宽"检验。

### 3.2 模型增项（v2.0，纯 CPU）

```
① 聚合带宽墙（替代隐式假设）
   W_ns(chunk) = 每块每 chunk 流量 × min(128, numBlocks) / BW_chip
   chunk_time  = max(copy_per_sm, W_ns, comp, L_min)      # 满占用时 W_ns == copy
   作用：把"深度不能降低带宽时间"写成显式约束；低占用时 W_ns 按块数折算（真实行为）。
② 候选下探 + 守卫软化（F4 修复）
   tile ∈ {32,64,128,256}；(BM,BN)=(32,*) 的寄存器/线程效率需新增一项
   守卫改为软惩罚：pen = max(1, (numSms/2)/numBlocks) 或直接加空泡时间
③ 结构化输出（工程必需）
   `[L1 Decision JSON] {...}` 一行，供胶水与证据台账机器解析（不再 grep 文本）
```

**不做的**（B 线明确排除，避免重蹈 F3）：每 operand 独立深度，除非在 A100 的
计算主导 regime 里被实测证明（见 4.2 的 P2b）。理由：在 4090 上它无法被证明。

### 3.3 placement（哪些 operand 进 smem）——保留为副线，不做主打

`isRead × (S+1)` 已经在做"进不进 smem"，缺的是**显式判据**：tile 内复用度
（窗口体积 / tile 体积）> 1 才值得 staging。这条能接上上游
`affine-data-copy-generate` 的缺口（无差别拷贝、单 buffer、容量只 warning），
是一段很好的 related-work 与讨论，但**不要当作主贡献**——它在 4090 上大概率
不改变任何决策（heat1d 类本来就不该 staging，窗口法已经等价处理）。

## 4. 预注册预测（写下来，等实测）

### P1 regime 判定：4090 上 depth 已饱和
4096³ FP32 GEMM，`comp/copy = 0.49`（搬运主导）。预测：任一 tile 下
`S ∈ {2,3,4}` 的实测展宽 ≤ 3%，而 `S=1 → 2` 有 ≥ 15% 的阶跃。
判据：展宽 ≤3% → 深度饱和判定成立；>5% → 判定被证伪，模型需加新机理。
（现有 64×64 组数据 0.5% 已支持，需在 128×256 组补一次。）

### P2 跨架构翻转（全篇最锋利的一条）
同一份代码、只重标 8 个常数：
- 4090：`comp/copy = 0.49` → 决策 128×256/TK=16/S=3（已实测 rank 3/48）；
- A100：`comp/copy = 1.70` → 模型预测 **64×128/TK=32/S=4**，且 S 维应出现
  **≥5% 的真实收益**（与 4090 的 ≤1% 形成对照）。

判据：A100 上 S=2 vs S=4 的实测差 ≥5% 且模型预测的配置进入前 20% → 主张成立；
若 A100 也平坦，则"regime 翻转"被证伪，退回 F2 的二值表述（仍可发表，但少一根柱子）。

### P2b 非对称深度的**有条件**准入
只有在 A100（计算主导）或低占用配置上，才做 `(S_A,S_B)` 网格。预测：A100 上
非对称最优会偏离对称最优（因为 `copy_A ≠ copy_B` 且 `comp > copy`）。
4090 上预测无差异（F3）——**不投入 oracle 时间**。

### P3 绝对精度（V0.3①）
`smBw = 7.21` 是在 heat1d（每元素 3 个独立读、MLP 强）上标的；GEMM 的 cp.async
4B 搬运达不到。预测：引入"有效带宽随访问形态修正"后，4096³ 的 −17.6% 乐观偏差
收到 ≤5%，且决策不变（排序由流量结构决定，不由常数决定）。

### P4 可移植性（F4 修复后）
512³ 在 142 SM 卡上修复后应有可行配置，且决策不是"最小 tile"（否则说明守卫软化
变成了新的偏置）。

### 5.1 第二架构：不必是 A100，但 4090 单卡不够撑 P2

P2（跨架构 regime 翻转）能不能成立，只取决于一个无量纲数
`comp/copy ≈ BM·BN / (k·(BM+BN))`，其中 `k = 2·smCompute/(4·smBw)`。
按规格换算（**未标定，仅看比例**）：

| 卡 | SM | 每 SM 带宽 | 每 SM FP32 | 128×256 的 comp/copy | regime |
|---|---|---|---|---|---|
| 4090 | 128 | 7.21 | 630 | 0.49（实测已证） | 搬运主导 |
| RTX 5060（本机） | 30 | 14.9 | 640 | ≈1.0 | **边界** |
| A100 40/80G | 108 | 14.4 | 181 | 1.70 | 计算主导 |
| H100 | 132 | 25.4 | 508 | 2.13 | 计算主导 |

结论：
- **本机 5060 只能做"敏感性"，不能做"翻转"**——它在 128×256 上恰好落在 1.0，
  而且 256×256（唯一明显翻转的方形 tile）被寄存器约束排除。写进论文只能当
  "边界情形"，不能当 P2 的证据。
- **A100 是唯一"干净翻转"且你组里已有**的选择。但它**不在关键路径上**：
  W1–W3 全是 4090，W4 才需要它，且只要 30 分钟标定 + 2 小时扫描。
- 排不上的降级方案：把 P2 从"支柱"降为"解析投影"（标注未实测），
  论文仍成立，但少一根柱子；此时第二卡用 5060 做常数迁移的敏感性分析。
