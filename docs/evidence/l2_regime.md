# L2 驻留 regime 项（#6）— 2026-11-18

> 依据：`python tools/l2_regime.py`、`python tools/replay_dev.py`
> 结论一句话：**加 regime 项是为了让"带宽量纲"正确；它不改变任何决策（β∈[1,4]），
> 也不是为了修 1024——1024 的 0.9pt 差异是噪声。**

## 1. 原模型的一个隐含假设

`copy = bytes / 7.21`，而 `7.21 = 922.8/128` 是**DRAM** 有效带宽的每 SM 均分。
该假设只对"工作集远超 L2"的情形成立：

| kernel | A+B+C 工作集 | 装得进 72 MB L2？ | 原模型误差 |
|---|---|---|---|
| 512³ | 3 MB | ✅ | **+77.6%** |
| 1024³ | 12 MB | ✅ | +31.9% |
| 4096³ | 192 MB | ❌（真走 DRAM） | **−13.9%** |

## 2. 改法（不改结构，只换带宽量纲）

```
W = (M·K + K·N + M·N)·4                       # 工作集字节
bw(W) = smBw × (L2_BOOST if W ≤ L2_BYTES else 1)
copy  = 面板字节 / bw(W) + cChunk
cWrite 仍用 smBw（输出写回走 DRAM，保守）
```

- `L2_BYTES = 72 MB`：**硬件属性**（下一步用 `cudaDeviceProp.l2CacheSize` 写进日志）；
- `L2_BOOST = 2.0`：L2 驻留时输入流式读的每 SM 有效带宽倍数。
  它与 `smBw` 属同一类量（实测有效带宽），不是新的拟合维度。

## 3. 决策不随它变（关键论据）

| L2_BOOST | 1.0 | 1.5 | 2.0 | 3.0 | 4.0 | 6.0 |
|---|---|---|---|---|---|---|
| 决策变化行数 | — | 0 | 0 | 0 | 0 | 1（gemm1024） |

⇒ 在 **[1, 4] 区间内，15 行决策完全不变**。所以它不是"用来自证结论"的项，
   只修正绝对量的量纲。

## 4. 绝对误差（次要收益，不作为论文的主张）

| β | 绝对误差中位 | 最差 |
|---|---|---|
| 1.0（原） | 42.2% | 77.6% |
| **2.0（取此值）** | **9.0%** | 71.4% |
| 3.0 | 28.4% | 71.4% |

β=3 会过度修正（512 从 +77.6% 变成 −20.1%），β=2 让 512/500/链/symm 落在 −8%~+2.5%。
4096 全程保持 −13.9%（不受影响，说明 regime 判定正确）。

## 5. 关于 gemm1024：它是并列，不是落后

| 配置 | 实测 | 距优 |
|---|---|---|
| `128/64/64/1`（oracle 最优） | 88.3 | — |
| `64/128/64/1`（3 行规则的选择） | 91.3 | +3.4% |
| `64/128/32/3`（模型的选择） | 92.1 | +4.3% |

模型与规则只差 **0.9 个百分点**，而该会话的顺序测量不确定度约 3–4%（同 tile 内 S≥2 抖动 3.0%）。
⇒ **1024 是并列，不能算"模型输给规则"**；也不应该为了这 0.9pt 再改模型（那是对噪声拟合）。

模型偏好 S≥2 的机理：S=1 用 `chunks×(copy+comp)`（完全不重叠），S≥2 用
`chunks×max(copy,comp,L_min)`。实测两者在 1024 上打平（91.3 vs 92.1），
说明真实 S=1 的重叠损失没有模型假设的那么大；但差异在噪声内，修它是过拟合。

## 6. 论文写法

> 有效带宽按两级标定：DRAM 驻留时 7.21 GB/s/SM（922.8/128 实测），
> L2 驻留时 14.4 GB/s/SM。regime 由工作集是否 ≤ L2 容量决定（硬件属性）。
> 该修正只改变预测的绝对量纲，**不改变任何决策**（倍数在 1–4 内，15/15 决策不变）。
