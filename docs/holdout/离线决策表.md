## 2. 可检查的点（跑批前）

1. **A1/A2 只在 5 个 kernel 上不同**（S1、R1、R3、R4、R9），与预注册 P3 的"GEMV/2D 应逐位相同"一致；
   若实际日志跑完发现这 5 个之外还有差异，先查代码路径，不当科学结果。
2. **A2 的 GEMM/链决策全部落在 96 KB**（R1/R2/R3/R4/R7/R9），与开发集"6/8 赢家在 96 KB"的容量现象一致；
   这批 kernel 是"容量 regime 是否在留出集复现"的直接检验。
3. **S1 是唯一被 L2 regime 改决策的流式行**（T256/S3 → T512/S1）；它是"L2 项到底有没有用"的单点检验。
4. **R2（999³，非整除）A1/A2 同决策**：cChunk 在非整除的 64/128 网格上没有翻决策；
   若实测 R2 的赢家是 128×128 且模型选 64×128，则是 tile 形状误差，不是深度误差。
5. **R5/R6/R8 的 T=16**：模型因"T<16 惩罚"避开 T=8；开发集 mvt/bicg 512 的实测赢家是 T=8。
   留出集 N=1536/2048 上 T=8 给 192/256 块，T=16 给 96/128 块——这是"thin 惩罚 vs 占用"的干净对照。
6. **S6（12M，DRAM）**：模型预测 1.69 ms；按 96 MB×8 步×2 pass 的流量估算应在 1.5 ms 量级，
   若实测远低于/高于此值，先查载具语义（sibling 交换）再谈模型。
