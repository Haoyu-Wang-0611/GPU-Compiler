## 0. v1 → v2 的七处改动

| # | v1 | v2 | 为什么 |
|---|---|---|---|
| 1 | 冻结版本写 v1.8.3 | **A1=v1.8.5、A2=v1.8.5+cChunk150+L2β2 两臂** | cChunk/L2 是 11-18 后验项，必须同场检验值不值 |
| 2 | 主指标混用 rank/top-20%/regret | **主指标 = tie-aware top-1 命中率**；rank/regret/双达标为副 | 老师要求三者不混用 |
| 3 | 只有 H1–H3 | 补 **H4 前沿覆盖（false-pruning）** 与 **H5 regime 预测**（H5 探索性） | 把"边界成立"变成可测判据 |
| 4 | "12 kernel" 但表里有 16 个 (类,尺寸) | **12 主 + 4 副**，主集固定；S5 载具未就绪时用 S7 **预注册替换** | 分母必须固定，替换规则必须先写 |
| 5 | B2 写"非整除 640/896"（其实都能被 64 整除） | **650/900** 真非整除；640/896 降为副集 | 口径错误 |
| 6 | 测量协议只在正文描述 | 定义**日志行格式**（`RESULT ...`）+ 旧格式兼容；R=5 round-robin | 四臂脚本要能机器解析 |
| 7 | 无系统一致性要求 | 增加"决策实现哈希"与"C++/Python 等价声明"栏 | 避免"两套系统"重演 |
| 8 | 尺寸选 384/768 | **R1/R3/R4=1152、R2=999、R5/R6=1536、S6=12M**；S5 明确 25 点 | 半机守卫下 <1024 的方阵只有 64×64 能过半机，测不到 tile 决策；S6 覆盖 DRAM 流区；"9 点 r=2"是笔误（r=2 完整邻域=5×5=25 点） |

## 1. 五个假设

| # | 假设 | 判据（主/副） |
|---|---|---|
| H1 | 冻结模型在未见 kernel 上稳定接近穷举最优 | 主：tie-aware top-1 命中率 ≥ 9/12；副：rank 百分位中位 ≤20%、regret 中位 ≤20%、双达标 ≥80% |
| H2 | 决策随结构/尺寸变化（不是查表） | 12 个 kernel 的决策参数去重 ≥4 组；且至少 3 个族内出现随尺寸翻转 |
| H3 | 接不住的结构给结构化拒因（适用域诚实） | 拒因率；任何"主表接得住、套件拒"都登记为缺陷 |
| H4 | 收缩后的前沿不误杀 oracle winner | **false-pruning = 0/12**（winner ∈ 前沿）；压缩率 96→k 中位 |
| H5 | 预测的 binding regime 是赢家贴住的那一面 | ≥10/12（**探索性，不参与 Go/No-go**） |

## 2. 冻结声明（实验批内禁改）

### 2.1 四臂

| 臂 | 定义 | 实现 | 说明 |
|---|---|---|---|
| **A0** | 三行规则 `R_full`：块数≥SM（不可达退 SM/2）→ 最大 tile 面积 → 最大 TK → S=1 | `tools/four_arms.py` 内置 | 强规则 baseline，不用模型 |
| **A1** | v1.8.5（`cchunk=0`、`L2_BOOST=1`） | `tools/holdout_decide.py --arm a1` | 旧主线 |
| **A2** | v1.8.5 + `cChunk=150` + `L2_BOOST=2` | `tools/holdout_decide.py --arm a2` | 当前默认；**尚未进 C++** |
| **A3** | oracle：同一候选空间穷举实测的最优 | 载具 sweep 日志 | 上界 |

### 2.2 候选空间（全族统一，不因 kernel 改）

- GEMM/链：`BM,BN ∈ {64,128,256}² \ {256,256}`，`TK ∈ {16,32,64}`，`S ∈ {1..4}` → 96 枚举；
- GEMV：`T ∈ {256,128,64,32,16,8}`，`TK ∈ {64,32,16}`，`S ∈ {1..4}` → 72 枚举；
- stencil-1D：`T ∈ {16,32,...,8192}`（不超过 N），`S ∈ {1..4}`；
- stencil-2D：`T ∈ {16,32,64,128}`，`S ∈ {1..4}`。
- 可行性：硬约束（smem/寄存器/结构）只由 A1/A2 的模型给；A0 只用"日志里实测存在 + 块数"筛。

### 2.3 并列规则（写死）

- 决策器内部：枚举顺序 BM→BN→TK→S 升序，首个严格更小者胜（与 v1.8.5 一致）；
- 分析侧：tie 阈值 `τ = max(2%, ε)`，`ε` = 每个 kernel 实测最快前 10% 配置的 IQR 相对值；
  与最优差 ≤τ 的配置并列 rank 1。

### 2.4 冻结文件与哈希

实验批开始前，在预注册里填入下列文件的 SHA256：`tools/holdout_decide.py`、`tools/four_arms.py`、
`daima/holdout/suite.json`、`docs/holdout/留出套件-spec-v2.md`。批内任何修改 → 本轮数据作废重跑。

> **C++/Python 等价声明**：A1 的决策与 `L1Feas.cpp` v1.8.5 逐位等价（15/15 自检）；
> A2 的 cChunk/L2 目前只在 Python。若 A2 胜出，论文的"系统证据"必须等 C++ v1.9 落地后重跑；
> 本套件先回答"决策质量"，不冒充"系统实现"。

## 4. 留出性定义（排除集）

一个 kernel 只有在 `(类, 尺寸)` 二元组都不在下列集合时才算留出：

- **标定源**：heat1d(N=1024/2²⁰/2²⁴)、jacobi1d(2²⁴)、jacobi2d(1024，interior 1022)、
  GEMM(4096/1024/512/500)、atax(8192)；
- **模板开发源**：twomm/3mm/mvt/bicg/symm/syrk(512³) 与全部探针（mvt/bicg/symm_full/symm_true/three_mm/syrk_probe/probe_dyn）。

主集全部满足。**诚实边界**：本套件是"**尺寸/半径留出**"，不是"模板留出"——12 个 kernel 仍落在
五类模板内；模板泛化只能靠"拒因率 + 结构派生论证"，不能靠这套件声称。

## 5. 测量协议

1. **R=5 round-robin**：外层 5 轮 × 内层遍历全部候选；每配置 5 个样本，取**中位数**；
2. **噪声带**：每 kernel 取最快前 10% 配置的样本 IQR 作为 `ε`；tie 阈值 `τ = max(2%, ε)`；
3. **正确性守卫**：每配置先跑正确性（PASS/rel_err），FAIL 不进排名；日志必须打印 PASS；
4. **日志格式**（新，优先）：
   ```
   RESULT kernel=<id> family=<gemm|gemv|stencil1|stencil2> \
          BM=.. BN=.. TK=.. T=.. S=.. time_us=.. pass=<0|1> sample=<0..4>
   ```
   旧格式（`BM=.. BN=.. TK=.. S=.. 耗时: X us` / `T=.. TK=.. S=.. 实测: X us` / `T=.. S=.. 实测: X us`）
   继续兼容；同一配置多行 → 取中位数。
5. **环境记录**：每次测量日志头必须记 GPU 型号、SM 数、`l2CacheSize`、时钟、占用状态（干净/污染）。

## 6. 指标定义（全部由 `tools/four_arms.py` 计算）

| 指标 | 定义 |
|---|---|
| 并列名次 | `1 + #(配置耗时 < best×(1−τ))` |
| rank 百分位 | 并列名次 / 该日志候选数 |
| regret | `t(arm) / t(best) − 1` |
| **命中（主）** | arm 配置与 best 差 ≤τ（tie-aware top-1） |
| 双达标 | rank 百分位 ≤20% 且 regret ≤20% |
| 前沿（frontier） | A2 的硬可行 + 占用收缩（空集回退）后的候选集合；`holdout_decide.py` 输出 |
| **false-pruning** | oracle winner ∉ frontier 的 kernel 数（目标 0） |
| 压缩率 | 96（或族候选数）→ frontier 大小 |
| 决策成本 | `holdout_decide.py` 单 kernel 墙钟（ms，PC，取 20 次中位） |
| 绝对误差 | `|predicted − measured| / measured`，报中位/最差（副） |
| regime 命中 | 预测 binding regime 与"赢家实测贴住的极值"一致（H5，探索性） |

**regime 判定（写死，避免事后贴标签）**：

- `capacity`：决策配置的 smem ≥ 0.9×cap，或"下一档 S/TK 会超 cap"；
- `occupancy`：blocks ≤ SM（且"下一档 tile 会使 blocks 掉到 SM/2 以下"）；
- `plateau`：日志中最快前 10% 配置的极差 ≤2τ；
- `guard/latency`：仅用于 syrk/GEMV 小 N；主集不含守卫 kernel，**不参与 H5**。

## 7. Go/No-go 与失败处置

**Go（全部满足）**：

1. 主集 12 个中 ≥10 个能测（否则套件无效，先补载具）；
2. A2 的 tie-aware top-1 命中 ≥9/12；
3. 双达标 ≥80%（≥10/12）；
4. false-pruning = 0/12；
5. 无 kernel 出现"模型决策不在实测集"（协议完整性）。

**处置**：

| 结果 | 处置 |
|---|---|
| A2 命中 ≥9 且 false-pruning=0 | 进入"完整版"：A2→C++ v1.9，写主表 |
| 边界成立（H4 过）但深度规律不成立（A2≈A1） | 去掉 "Depth Is Derived"，保留前沿剪枝 + 直接选择 |
| A2 < A0（中位 regret 更差） | **cChunk/L2 作废**，回 v1.8.5；论文只写可行性 + 规则/模型对照 |
| false-pruning >0 | 前沿实现有 bug：先修，修完**全量重跑**，不得只补失败项 |
| 命中 <9/12 | 按老师三叉判据降级；在 limitation 如实报告 |

## 9. 风险

1. **S5/S7 载具**：通用半径 stencil 是新增载具；若 r>1 的 1D 老分支记账有偏差，正好是 H3 数据，
   但也会拖慢主集 → 先做 S1/S3 的 r=1 vs r=2 对照，再决定是否把 r=2/3 全放进主集。
2. **R=5 交错骨架 retrofit**：6 个载具各 ~30 min；若来不及，先保证每个配置 5 样本、按轮次记录，
   分析侧仍可算中位数/τ。
3. **A0 规则在链/GEMV 上的定义**：`R_full` 原本是 GEMM 规则；本 spec 把它参数化到各族，
   **规则实现必须冻结并与 A1/A2 同一份 `four_arms.py`**，避免"规则被弱化"的质疑。
4. **测试集污染**：留出批必须在干净卡跑；每份日志头记占用状态，污染轮直接作废。
5. **A2 未进 C++**：若 A2 胜出，C++ v1.9 的回归 + rebase 是额外 1–2 天，已计入三个月排期。
