## 明确建议
**不要按 DeepSeek 原文直接切换论文主线。写作上先保留现有直接解析选择框架作为可落地基线；先用 48 小时统一算法、复现存量日志并核查反例，通过初筛后，再用约 10–14 天完成独立留出验证。只有全部通过，才把论文切换到收窄后的新主线。**

新思路的潜在价值高于单纯“又一个 cost model”：它试图解释何时不需要经验调优，并给出可证伪预测。但当前文档把经验现象写成了普遍定理，且混用了不同算法、模型选择和实测最优，直接采用会放大审稿风险。

## 不能直接采用新文稿的原因

### 1. 文档内部证据没有完全对齐
- `DeepSeek思考.md:60` 称 S>1 只在 4096 和链上有价值，但其主表 `:34-35` 的 heat1d 模型 S=1 分别距优 +18%/+4%，实测赢家为更深流水；“深度塌缩到 1”不能作为普遍结论。
- `:83` 声称 15/15 边界验证，但 `:85-96` 的表按 shape 计数只覆盖约 13 个，缺少 GEMM500 和 heat1d 2²⁰。
- `:96` 把 syrk/symm 的“赢家”写成 64×64/TK32/S4，这实际是模型选择；原始日志的实测最优分别是 syrk TK16/S3、symm TK64/S2（`daima/stril_syrk_512_v2.log:66-76`、`daima/stril_symm_512_v2.log:66-73`）。模型选择与 oracle winner 必须分列。
- `:130` 的“15 个 shape 上 rank 1–3”与主表已有 rank 4、rank 9、rank 6–8 不一致；按该表重算为 12/15 个 rank≤3、4/15 个 rank 1，不能写成全部 rank 1–3 或 5 个 rank 1。
- `derived` 的 16/16、最差 +1.9% 是事后规则重算结果，当前目录未见统一决策器实现和对应原始输出；当前代码仍显式枚举 S=1..4（`daima/L1Feas.cpp:822-825`）。T1、T2 和摘要不能拼成同一个系统的证据。

### 2. “最优永远在边界”目前缺少数学条件
- shared memory/register 是硬资源约束；`blocks ≥ SMs` 或 `≥ SMs/2` 是当前性能/可测性启发式，不是程序可执行性的硬可行条件。二者不能混成一个数学可行域后再宣称最优性保证。
- 文档假设时间在 tile/TK 上单调下降、在深度上单调不增（`:77-81`），但又记录 max_tile 在 512 上崩 5.5×（`:51`）以及深度伤害案例（`:62`）。这些现象本身就否定无条件的单调性。
- 离散候选中“下一档超限”不等于连续意义上的“约束取等号”。更合适的定义是离散资源/Pareto 前沿或最大可行点，并单独测量前沿大小；目前没有依据声称普遍只有 O(常数) 个候选。
- “或落在 plateau”使边界定义过宽。若不预先定义平台和边界，几乎任何赢家都能事后贴标签，失去可证伪性。

### 3. 深度探针支持的是更细的结论，不是简单的 S=1
`bufprobe.cu` 将缓冲份数 B 与预取距离 D 解耦。若性能主要随 D 饱和、B 只需满足最小流水要求，那么合理结论应是“分别导出 D 与最小 B”，而不是当前耦合参数 S 普遍塌缩为 1。还需要验证它与 MLIR `iteration_interval` 的语义对应。载具里的 S=1 实际仍对应 B=2、D=1，不能笼统写成“完全无缓冲/无流水结构”；GEMV 的 S=1 也可能只是深度不敏感时枚举顺序保留的并列解，而非物理定律。

### 4. Novelty 不会因改名自动成立
CC 2012 已用解析 cache footprint 限定 tile 搜索子空间；ICS 2021 已做资源约束下的 affine GPU tile 选择；ALCOP 有 tiling/pipelining 协同权衡和 analytical-only ranking。新路线必须证明“前沿 oracle 覆盖 + 无需执行反馈的直接选择 + 条件化深度规律”的增量，而不能只声称“边界”一词此前无人使用。

## 推荐的“48 小时初筛 + 10–14 天验证”路线

### 第 1–2 天：统一算法与证据口径
1. 冻结当前 v1.8.5 为旧主线基线，不再为了让旧主表更漂亮而新增 `cChunk` 等拟合项。
2. 将 `derived` 写成唯一、确定、无 kernel 特判的可执行决策函数；固定边界定义、深度规则、候选集和 tie-break。
3. 用同一实现对全部开发日志自动重算，输出三列：模型配置、实测最优配置、预测紧约束。复现不了声称的 16/16，就停止当前新叙事；同时定义“命中”究竟是 direct top-1、top-20% 还是 regret≤20%，不得混用。
4. 在初筛内补三个小核查：syrk/symm 模型与 oracle 配置对照、一个 GEMV 噪声并列对照、两个未见 shape 的小型 (D,B) 网格。单点 B/D 现象未跨 shape 复现前，不进入完整深度导出叙事。
5. 修正上述表内矛盾；T1/T2/摘要必须来自同一算法和同一批日志。

### 第 3–5 天：形式化边界并主动寻找反例
1. 分开声明：
   - 硬可行性：shared memory、register、结构/同步合法性；
   - 性能剪枝：full/half-SM、wave、lane×DRAM 等启发式。
2. 对离散候选定义资源前沿/Pareto 前沿，不再用“至少一条不等式取等号”替代所有情况。
3. 主动检查 wave quantization、cache 命中、bank conflict、寄存器变化、深度惩罚和非整除 shape 是否产生内部最优点。
4. 若不能证明定理，论文只提“高覆盖资源前沿剪枝”，不提“最优永远在边界”。

### 第 5–12 天：一次性独立验证
复用现有留出 spec（`memory/2026-11-15.md:85-94`），在看到结果前冻结模型和规则：
- 同一留出套件比较当前 v1.8.5、boundary/derived、tile-only、最佳固定深度、双向顺序策略；ALCOP 完整流程与 analytical-only 仍按原计划准备，不能因换叙事取消。
- 使用 R=5 round-robin、每配置中位数/IQR、tie-aware rank；小 kernel 的 3–5% 差异必须超过噪声区间才解释。
- 报告：前沿大小/压缩率、实测最优是否被保留、false-pruning、top-20%、regret、严格 rank 与并列 rank、决策成本。
- 深度阈值必须在开发集预先确定，再跨至少两个 kernel 族和多个未见尺寸验证；不能只凭 512/1024/4096 反推一个阈值后宣称普遍成立。

### 切换判据
只有同时满足以下条件才采用修改后的新主线：
1. 单一冻结算法复现开发集结果，没有事后逐 kernel 修规则；
2. 前沿在独立套件上保留实测最优或预注册允许的近最优，且无灾难性 false-pruning；若主张“最优在边界”，oracle recall 应接近 100%，只有 80% 时只能主张经验剪枝；
3. derived 的决策质量不差于当前模型和强固定/顺序基线，同时候选数或决策成本有明确优势；
4. 深度规律在未见 kernel/尺寸上超过统计噪声，而非只在旧日志成立。

若边界成立而深度规律不成立，只把前沿剪枝并入直接解析选择，不使用“Depth Is Derived”作为主标题。若边界也不成立，放弃新主线，回到当前直接选择及 ALCOP 质量—成本对照。

## 两条路线都必须遵守
- ALCOP 的 79%/92% 已核实为 analytical model 排名后分别取 top-10/top-50 去实测、再取最佳性能的归一化结果，不是 direct top-1 的预测准确率。公平比较应在同一套件上报告 top-k 质量—实测成本曲线，包含本方法 top-1 无执行反馈决策，不能只抄两个百分比。
- 不用不同硬件/后端的已发表百分比直接宣称优于 ALCOP/ICS；baseline 跑不动时只能限制结论，不能把间接数字拼成胜负表。
- “Measurement-Free”改为“无编译/执行反馈在环”，因为离线硬件校准仍需要实测。
- 不再声称“首次联合”“绝对全局最优”“任意 kernel 零非法”；所有结论限定于支持模板、候选空间、硬件和测量协议。
- 保留 GEMM + stencil 的 MLIR→PTX→执行垂直切片；两条路线都不能把手写 CUDA 结果写成生成 IR 的端到端性能。

## 推荐的新主线表述（仅在关卡通过后）
**面向规则 GPU loop nests 的资源前沿直接配置选择：利用硬资源约束与经独立验证的并行度剪枝构造高覆盖候选前沿，在无编译/执行反馈内循环的条件下逼近穷举决策质量，并给出流水预取距离何时可导出的适用条件。**

这是一种可证伪、可证伪失败后收窄的方法贡献，而不是“所有最优永远在边界、深度不再是搜索维度”的普遍定理。
