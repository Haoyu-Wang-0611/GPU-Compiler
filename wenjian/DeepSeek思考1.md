# 论文方向重构：从"联合决策"到"边界解"

> 2026-11-15，DeepSeek 会话产出。基于 11-01～11-15 全部实验、16 份 oracle 日志、5 份 golden、
> 一次拆 B/D 探针、三轮干净卡复测，以及我自己推翻的三条中间结论。
> 这份文档只谈"论文该是什么"，不谈实现细节。

---
## 0. 一句话

### 对于规则访问的 GPU 循环嵌套，最优配置永远落在"可行域的边界"上——占用率与容量这两类不等式决定了它；而在边界上，tile 与深度争抢同一份容量预算，tile 的边际收益压倒深度，所以深度塌缩到 1。于是配置决策是闭式的，不是搜索；这也解释了为什么自动调优的收益几乎全部集中在 tile 上。

### 1.2 五策略：搜索这一维不需要

在 17 份日志上重算"决策规则"，相对同日志实测最优：

| 策略                                                  | 结果                    |
| --------------------------------------------------- | --------------------- |
| `derived`（深度算出来（每个 tile 组取"装得下最大的 S"），只在 tile 上选最优） | **16/16 命中，最差 +1.9%** |
| `seq`（先假设不流水（S=1）选出最好的 tile，再给这个 tile 定 S）          | 16/16 命中，最差 +3.2%     |
| `tile_only`（完全不流水）                                  | 亏 0–18%               |
| `max_tile`（简单粗暴：装得下的最大 tile，别的不管e）                  | 4096 命中；512 崩 5.5×    |

### 1.3 深度：它不是搜索维度

拆 B（缓冲份数）/ D（预取距离）的探针（512³、128×128/TK16）：
	- **B = 缓冲份数 = S+1**：共享内存里放几份数据（决定占多少 smem）；
	- **D = 预取距离 = S**：提前几个 chunk 开始搬（决定流水多深）。
- D=1（B=2/3/4）：84.5 / 84.6 / 84.6 ns·µs 级 → **B 无关**
- D=2：81.0–83.2；D=3：80.8；D=4：82.7 → **时间只跟 D 走，D 在 2–3 饱和**

- **S>1 只在两处值钱**：4096³（+2.9%）和链（2mm/3mm，+5.1%）。其余四个族的赢家都是 S=1。
- **"驻留假设"作废**：我们之前猜"smem 一大，每个 SM 放的块就少，所以变慢"。实测 4090 每 SM 只有 **100 KB**（不是 128 KB），而且让驻留从 3 块降到 1 块，时间**反而略快**。所以那个猜测是错的，已撤回。
- **深度伤人的唯一稳定案例**：atax 在 N=8192、T=8 时，S 从 1 加到 4 慢 **31%**。但同样是 T=8 的 bicg@512 只有 ±6% 抖动。**区别在数据在 DRAM 还是在 L2**。所以结论要写成双条件："lane 不足 **且** DRAM 流"。

### 1.4 测量：环境是证据的一部分

- 干净卡：4096 跨 3 会话逐配置 0.3–0.5%；512 复现 11-14 的 24.1→24.2（0.4%）。
- 污染：整轮 +12%（512 的两份日志）；**<半卡配置 20–70%**。
- ⇒ **半机守卫（numBlocks ≥ SMs/2）同时是性能边界与可测性边界**，这是它此前没有的理论依据。

## 2. 从证据里长出来的两个陈述（论文的骨头）

### 2.1 边界解：最优配置落在可行域的边界上

**三条不等式（三面墙）：**
1. **占用墙**：`blocks ≥ SM 数`（128）。到不了就退一步 `≥ 64`（半机）。含义：GPU 有 128 个 SM，你切出的块至少要能填满它们，否则有核在空转。
2. **容量墙**：`(S+1) × 单份字节 ≤ 99 KB`。含义：共享内存就这么大，多一份缓冲、大一点 tile 都要占地方。
3. **寄存器墙**：`每线程寄存器 × 线程数 ≤ 每 SM 寄存器`。256×256 就是撞在这面墙上。

**为什么最优一定贴墙**：沿着"更大 tile"或"更大 TK"的方向走，时间**单调下降**（因为搬运总量在减少）；那你就一直往前走，直到被某面墙拦住为止——**停下的地方就是墙边**。如果某片区域是"高原"（比如 heat1d 带宽饱和，T=1024 和 T=4096 一样快），那站哪儿都一样，也不会在"中间某个特殊点"。

**15/15 验证表怎么读**：每一行告诉你"这个 kernel 的赢家，被哪面墙拦住"。

- 4096：`128×256/TK16/S3` = 96 KB，S=4 就要 128 KB → **容量墙**；
- 1024：`128×64/TK64/S1`，若用 256×64 只剩 64 块 < 128 → **占用墙**；
- 512：`64×64/TK64/S1`，已经到"最多 64 块"的极限 → 占用墙；
- 2mm/3mm：`64×64/TK64/S2` = 96 KB，S=3 就 128 KB → 容量墙；
- atax：T=64 → 128 块正好满；T=128 就只剩 64 块 → 占用墙；
- mvt/bicg：T=8 → 64 块（半机）；T=16 就 32 块 → 占用墙；
- jacobi-2d：T=64 可行，T=128 要 134 KB → 容量墙。

**"紧的约束"** = 等号成立，正好卡满。

**为什么这是论文的骨头**：它把"调参"从"在空间里瞎试"变成"解三条不等式"，而且给了一个**能被实验打死的预测**：以后任何一个新 kernel，它的最优都该在墙边。**能被证伪的预测，才是科学的说法；"我们效果不错"不是。**

**为什么这是论文的骨头**：它把"调优"从"在二维/三维空间里搜"变成"解三条不等式"，并且给出一个
**可证伪的预测**——任何新 kernel 的实测最优都应当是边界点。这一条比"我们的决策很准"硬得多，
也正好是 EATSS/ICS'21（解析 tile，无占用维度）与 ALCOP/Twill（有搜索、无边界刻画）都没有的东西。

### 2.2 容量预算竞争：深度为什么塌缩到 1

**陈述**：tile 面积、TK、缓冲份数 `(S+1)` 三者共享同一份容量预算。在边界上，tile 的边际收益（直接降流量 ∝ 1/BM+1/BN）远大于深度的边际收益（只摊薄每 chunk 的固定开销），所以**深度是先被牺牲的那一项**：只有当 tile 已经顶到占用率上限、容量还有富余时，深度才拿得到预算——而那正是4096 与链（+3~5%）；其余情况深度 = 1。

**证据**：512/1024 的赢家 S=1；4096 的赢家 S=3（容量没有更好的用途）；拆 B/D 探针说明 D≥2 之后
时间不再改善（饱和）。**推论（可证伪）**：`chunks × waves`（每 block 的流水长度 × 波次数）小于
某个阈值时，S>1 无收益。现有数据：4096 → 256×4 = 1024（有收益）；1024 → 16×1 = 16（无）；
512 → 8×1 = 8（无）。

## 3. 论文身份（该写成什么）

### 3.1 标题候选

- *Boundary Solutions: Occupancy-Constrained, Measurement-Free Configuration Selection for MLIR GPU Kernels*
- *Depth Is Derived: How Occupancy and Capacity Determine GPU Tile and Pipeline Choices*
- 中文口径：**"边界解"：占用率与容量决定的 GPU 配置选择——深度不是搜索维度**

### 3.2 摘要式主张（四句，全部有数据）

1. 配置决策的最优解落在可行域边界上，可行域由占用率/容量/寄存器三条不等式解析给出（15/15）。
2. 因此决策是闭式的：先解边界，再在边界上按流量排序；深度由容量与流水长度导出，**默认 1，仅在最大规模处取 2–3**（17 份日志、400+ 配置）。
3. 一个 MLIR 中端 pass 实现它：毫秒级、零实测在环、零非法配置；15 个 shape 上 rank 1–3，中位距优 +4%，5 个命中全空间最优。
4. 代价：绝对时间误差 −17%～+71%（决策与标定分离）；边界项（lane×DRAM、守卫粒度、链 launch） 已登记并给出判据。

## 4. 与已有工作的定位（一句话各）

| 工作 | 它做了什么 | 我们的差异（可辩护） |
|---|---|---|
| ALCOP (2022) | TVM 里联合搜 tile + 每 buffer stage；解析模型 + XGB + 退火；容量只进 occupancy 模拟 | 我们**硬可行域 + 无实测 + 边界刻画**；它的解析-only 只有 79%/92% |
| Twill (OSDI'26) | TTGIR 上 ILP+SMT 求 SWP+warp specialization，硬容量约束，19–269 s，**tile 是外部输入** | 我们闭式、ms、含 tile；不求解，只解不等式 |
| EATSS (CGO'24) / ICS'21 / TileMind | 解析/多面体 tile 选择，无深度、无占用三层 | 我们 ~96–100% of best、零非法；它们 ~75% |
| PEAK (MLIR/IREE) | 调度 DSL + autotuner；**无 software pipeline 原语** | 我们的深度决策是 MLIR 上的空白填补 |
| TileSight 等 | 解析性能模型，只评估不决策 | 我们端到端给配置 + 发射 |

**注意**：不要再把"tile×depth 联合"当卖点（ALCOP 已占且我们的数据反对）。卖点是
**"边界解 + 深度导出 + 零非法"**。

## 8. 给导师的说法（可直接讲）

> 我们原计划做 placement × 多缓冲深度的联合决策。这一阶段用预注册实验把这个假设检验掉了：
> **placement 由窗口法唯一确定，深度由容量与流水长度唯一确定，两者都不是需要搜索的维度**；
> 真正要决定的是 tile，而它的最优解落在占用率/容量可行域的边界上——这一条在 11 个 kernel、
> 15 个 shape 上 15/15 成立。
>
> 这比原来的"联合"更强：它把三维搜索降成解三条不等式，给出毫秒级、零非法、可解释的选择，
> 并且解释了一件领域内一直含糊的事——为什么自动调优的收益几乎全在 tile 上、深度往往"调了也没用"。
>
> 论文的主张从"我们联合优化"改成"我们能证明什么时候不需要搜索、需要搜索时边界在哪"。

## 9. 本轮新增的三条可证伪预测（写下来等验证）

1. **边界点预测**：任何新 kernel 的实测最优，都应在至少一条约束上取等号（容量 96–99 KB、
   占用 blocks = SMs 或 SMs/2），或落在带宽平台上。→ 留出集上检验，命中率 ≥80% 即成立。
2. **深度阈值**：`chunks × waves ≥ 某值` 时 S=2 的收益 ≥3%，否则 ≤1%。→ E2 检验。
3. **lane×DRAM 双条件**：同 lane 不足下，DRAM 流（大 N）才有深度惩罚，L2 驻留（小 N）没有。
   → 现有 atax@8192(+31%) vs bicg@512(±6%) 已支持；再补 atax@512 一轮即可定案。

## 10. 一句话收尾

**你手里已经不是一个"调参器"，而是一条关于 GPU 配置空间的结论：最优解在边界上，深度是边界上的剩余变量，因此调优真正需要决定的东西只有一件——tile 有多大，而这件事可以算出来。**
剩下的工作不是找新发现，而是把这条结论钉在留出集上、写清楚边界，然后投出去。
